## 📖 项目简介

**银发守护**是一款面向独居老人的**手环+桌面Hub双端AI守护系统**，解决"老人离开桌面终端即失联、突发状况家属无从知晓"的痛点问题。

### 核心亮点

- 🆘 **SOS一键呼救**：手环按键，秒级通知家属
- 🪑 **久坐/静止检测**：六轴IMU，智能识别异常状态
- 💊 **用药提醒**：Hub大字显示+语音播报，手环同步
- 🎤 **语音闲聊**：情感陪伴，健康数据语音记录
- 📱 **异常告警**：多级推送，确保家属知晓
- 🚦 **分色指示灯**：不看屏幕也能从灯色分辨告警级别

### 当前进度（2026-09-13）

| 端 | 状态 | 说明 |
|---|---|---|
| **Hub端** | ✅ **已上板可交互** | 触摸界面、中文字库、板上传感器、持久化、WiFi联网、SNTP校时、分色指示灯、板间联动接收 —— 全部真机验证 |
| **手环端** | 🔄 开发中 | 应用框架已搭，待硬件调试与联动对接 |
| **云端** | ⏳ 本地桩 | 事件/告警接口已预留，待对接真实服务 |

## 🎯 问题背景

中国已进入深度老龄化社会，独居老人数量持续增长。现有智能穿戴设备存在明显痛点：

- **失联问题**：老人离开桌面终端后，家属无法知晓其状态
- **响应延迟**：突发状况时，无法第一时间通知家属
- **功能单一**：传统手环仅有健康监测，缺乏主动关怀
- **交互困难**：老人对复杂智能设备操作困难

**银发守护系统**采用**手环+桌面Hub双端协同架构**，实现全天候、全场景的老人守护。

> **板间通道用 WiFi 而非 BLE**：Hub 与手环接同一个 WiFi，手环以 UDP 向 Hub
> 的 5555 端口发报文。UDP 无需握手重连，Hub 重启后手环不用做任何恢复动作；
> 可靠性交给应用层重发（告警连发 3 次 + 定期重发）。
> 协议详见 [`docs/开发文档/17_板间联动协议.md`](docs/开发文档/17_板间联动协议.md)。

## 🔧 硬件选型

### 手环端：黄山派SF32LB52

**选择理由**：
- ✅ 专为穿戴设备设计，低功耗优化
- ✅ 六轴 IMU 集成，运动检测精准
- ✅ LCD 驱动支持，界面友好
- ✅ openvela 系统支持，开发便捷

**核心参数**：
- 处理器：ARM Cortex-M4F @ 64MHz
- 传感器：六轴 IMU（加速度+陀螺仪）
- 显示：LCD 屏幕（支持 LVGL）
- 功耗：超低功耗设计，续航7天+

### Hub端：润芯微Gemini-S1 ✅ 已上板

**核心参数（实测确认）**：
- 处理器：全志 R528-S3，ARM Cortex-A7 双核 @ 1.2GHz
- 内存：128MB DDR3 / 256MB SPI NAND
- 显示：板载 2.8 寸 SPI 屏（320×240，电阻触摸）
- 无线：**RTL8733BS，802.11a/b/g/n 双频（2.4G + 5G）+ 蓝牙 5.2**
- 音频：板载麦克风；**无板载扬声器**，需外接（见下方"硬件限制"）
- 传感器：SHTC3 温湿度、LTR-553 光照/接近、SGP30 空气质量
- 指示灯：**WS2812B 可寻址 RGB**（原理图 LED4，走 LEDC 控制器）
- 供电：5V/2A（DC 3.5×1.35mm 或 USB Type-C）

### ⚠️ Hub端硬件限制（实测踩过，别当成 bug）

| 现象 | 原因 |
|---|---|
| **喇叭没声音** | 板子**没有板载扬声器**。需外接 **4Ω 3W、1.25mm 2pin 端子**的喇叭，插板子右侧边 `SPK_L` / `SPK_R` 座（原理图 CN1/CN2） |
| 耳机只有绿色口有输出 | 顶边三个 3.5mm 座：**绿色=HPOUT**（耳机）、紫色=FMIN、橙色=LINEIN，只有绿色是输出 |
| SGP30 的 CO2/TVOC 读不到 | 芯片无响应（硬件层）。健康页如实显示"未检测到"，不伪造数据 |
| 日期会回到 1970 | **板子没有 RTC 备份电池**（只有 VCC_RTC + 32.768K 晶振，无纽扣电池）。已用"固件构建日期兜底 + 联网后 SNTP 校时"解决 |
| 手动驱动 PB10 点不亮 LED | 硬件手册写的 `SYS_LED=PB10` 在这块板子上不成立。真正可见的是 WS2812 |

## 📋 核心功能

### 1. SOS 一键呼救 ⚠️

**流程**：
1. 老人长按手环 SOS 按键（3秒）
2. 手环通过 WiFi 发 `SG1 SOS` 到 Hub
3. Hub **立刻**：红色指示灯快闪 4Hz + 屏幕弹出"紧急求助"警示层 + 提示音
4. WiFi 推送告警到家属手机（云端对接中）
5. 老人点屏幕"知道了" → 指示灯与警示层一起收起

> Hub 侧**已实现并上板验证**接收端；手环端发送端开发中。
> 当前可用电脑发一条 `SG1 SOS` 直接验证整条链路。

### 2. 久坐/长时间静止检测 🪑

**流程**：
1. 手环六轴 IMU 持续采集运动数据
2. 端侧算法判定久坐时长
3. 手环发 `SG1 SITTING <秒>` 到 Hub
4. Hub：**黄色**指示灯慢闪 1Hz + 屏幕显示"您已静坐 N 分钟"
5. 老人恢复活动 → 发 `SG1 RESUMED` → Hub 收灯收警示层

### 3. 用药提醒 💊 ✅ 已实现并上板

**流程**：
1. 在 Hub 屏幕上直接添加用药计划（时间/药名/剂量），存 `/data` 断电不丢
2. 到点触发：**绿色**指示灯慢闪 1Hz + LCD 大字显示"该吃药了\n请服用 XXX" + 提示音
3. 老人点"知道了"收起；30 秒无人理会则灯自动熄灭（不会闪到天亮）
4. 手环端接入后由 Hub 反向推送（协议预留）

### 4. 网络配置（Hub端独有）📶

- **设置 → 网络设置**：扫描附近 AP → 列表显示 SSID 和 dBm → 点选 → LVGL 全屏键盘输密码 → 连接
- 内置了 5GHz 关联、DHCP 取址、配置持久化的完整处理（详见下方"技术方案"）
- 联网后自动 SNTP 校时，顶部状态栏如实显示"已联网"/"离线"

### 5. 异常告警分级 🚦

| 级别 | 触发 | Hub 反馈 |
|---|---|---|
| 🔴 紧急 | SOS / 跌倒 (`SG1 SOS` / `SG1 FALL`) | 红灯快闪 4Hz（保持 5 分钟）+ 警示层 + 提示音 |
| 🟡 提醒 | 久坐 (`SG1 SITTING`) | 黄灯慢闪 1Hz（30 秒）+ 警示层 |
| 🟢 用药 | 用药到点 | 绿灯慢闪 1Hz（30 秒）+ 警示层 |

## 🚀 编译与烧录（Hub端）

### 环境准备

```bash
# 1. 安装 WSL2 Ubuntu 24.04
wsl --install -d Ubuntu-24.04

# 2. 拉取 openvela 工程
repo init -u https://github.com/open-vela/contest2026_325_junweiyanjiuyuan \
  -b dev-ai-contest-2026 -m contest2026_325_junweiyanjiuyuan.xml
repo sync -c -j8

# 3. 进入工作区
cd ~/contest2026_325_junweiyanjiuyuan
```

### 编译（一条命令）

```bash
bash tools/build_hub.sh
```

脚本固化了**不能换顺序**的五步：

```
pull(C→A) → gen_fonts → push(A→B,C) → 强制 touch 全部 .c → build → strings 校验
```

每一步都是踩坑换来的，详见 `docs/开发文档/15_Hub端完整编译烧录实操手册.md`。

### 打包成可烧镜像

```bash
bash tools/pack_hub.sh
# 产物：C:\Users\<你>\flash_sg.img
```

⚠️ **别直接跑 lichee 的 `pack`** —— 那样 fes1/boot0 不是出厂版，烧录会卡 0%。

### 烧录

1. 打开 `tools/PhoenixSuit_new/PhoenixSuit.exe`
2. 一键刷机 → 选镜像（**纯英文路径**）
3. 模式选「全盘擦除升级」→ 刷机
4. **板子断电 3~5 秒再上电**（物理触发 FEL，比 adb reboot 可靠）

## 🤖 AI Coding 使用说明

### 开发工具

- **Claude Code**：主要 AI 辅助开发工具
- **用途**：需求分析、方案设计、代码编写、调试优化、文档生成

### 日志管理

- **日志位置**：`logs/harryminei/<日期>/claude-code__<session>.jsonl`
- **格式**：每行一个自包含元数据的 JSON（`schema_version`/`session_id`/`team_id`/`github_login`/`tool`/`seq`/`ts`/`role`/`text`）
- **清单**：`logs/harryminei/manifest.json` 登记全部会话
- **提交方式**：随代码一起提交到 GitHub

### AI 在本项目里的实际作用

不只是"生成代码框架"。Hub 端从 08-24 到 09-13 的关键推进，很大一部分是
**定位反直觉的根因**，这些都不是靠读文档能得到的：

- 硬件手册写的 `SYS_LED=PB10` 实际点不亮，真机对比实验后改用 WS2812
- 驱动关联 5GHz AP 必须先 `wapi freq ... FIXED` 钉信道，否则永远 `candidate == NULL`
- NuttX 自带 `ntpclient` 有 argv 错位 bug（服务器列表填了却恒为 NULL），改用应用侧 SNTP
- 这个 app 没有 `src/Make.dep`，**只改 `.h` 不改 `.c` 的改动永远进不了固件**
- LTO 全量链接下，裸 `led_off()` 会和厂商 `luncher_mini` 的符号撞车

完整对话日志见 `logs/harryminei/`。
