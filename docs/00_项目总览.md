## 🎯 项目概述

### 问题背景

中国已进入深度老龄化社会，独居老人数量持续增长。现有智能穿戴设备存在明显痛点：

- **失联问题**：老人离开桌面终端（如智能音箱）后，家属无法知晓其状态
- **响应延迟**：突发状况（跌倒、心脏病发作等）时，无法第一时间通知家属
- **功能单一**：传统手环仅有健康监测，缺乏主动关怀和紧急响应能力
- **交互困难**：老人对复杂智能设备操作困难，需要更友好的交互方式

### 解决方案

**银发守护**系统采用**手环+桌面Hub双端协同架构**，实现全天候、全场景的老人守护：

- **手环端**（黄山派SF32LB52）：全天佩戴，实时健康监测，紧急呼救
- **Hub端**（润芯微Gemini-S1）：桌面固定，语音交互，数据处理，家属通知
- **云端AI**：智能对话，数据分析，异常识别，消息推送

### 核心价值

- ✅ **全场景覆盖**：室内室外、活动休息，24小时不间断守护
- ✅ **即时响应**：SOS一键呼救，秒级通知家属
- ✅ **智能预警**：久坐提醒、异常检测，防患于未然
- ✅ **情感陪伴**：语音闲聊，缓解老人孤独感
- ✅ **操作简单**：大字体、语音交互，老人友好

## 📋 核心功能

### 1. SOS 一键呼救 ⚠️

**场景**：老人突发状况（跌倒、心脏病发作、紧急情况）

**流程**：
```
1. 老人长按手环 SOS 按键（3秒）
   ↓
2. 手环震动确认，屏幕显示"SOS已发送"
   ↓
3. BLE 通知 Hub 端
   ↓
4. Hub 端扬声器播报："已收到求助，正在通知家属"
   ↓
5. Hub 通过 WiFi 推送告警到家属手机
   ↓
6. 家属收到短信/APP推送/电话通知
```

**技术要点**：
- 手环端：按键中断处理，BLE GATT 通知
- Hub端：事件优先级最高，立即响应
- 云端：多通道消息推送（短信+APP+电话）

---

### 2. 久坐/长时间静止检测 🪑

**场景**：老人长时间不活动，可能存在健康风险

**流程**：
```
1. 手环六轴 IMU 持续采集运动数据
   ↓
2. 端侧算法判定：
   - 久坐超过 60 分钟 → 提醒
   - 静止超过 2 小时 → 告警
   ↓
3. 手环震动提醒，屏幕显示提示
   ↓
4. BLE 上报 Hub 端
   ↓
5. Hub 端语音播报："您已经坐了很久了，起来活动一下吧"
   ↓
6. 数据记录到云端，生成健康报告
```

**技术要点**：
- 手环端：低功耗 IMU 采集，端侧 AI 判定
- 阈值可配置：家属可通过 APP 调整
- 误判过滤：排除睡觉、乘车等场景

---

### 3. 用药提醒 💊

**场景**：老人需要按时服药，避免遗忘

**流程**：
```
1. 家属通过 APP 设置用药计划
   （药品名、时间、剂量、备注）
   ↓
2. 到达提醒时间，Hub 端触发提醒
   ↓
3. Hub 端 LCD 大字显示：
   "该吃药了！
    药品：降压药
    剂量：1片
    时间：08:00"
   ↓
4. Hub 端扬声器播报用药信息
   ↓
5. 手环屏幕同步显示，震动提醒
   ↓
6. 老人确认后，记录服药时间
   ↓
7. 未确认则重复提醒（最多3次）
```

**技术要点**：
- Hub端：定时任务调度，LCD 大字体 UI
- 手环端：BLE 同步显示，震动反馈
- 云端：用药记录，家属可查看依从性

---

### 4. 语音闲聊与健康数据记录 🎤

**场景**：老人感到孤独，需要情感陪伴；需要记录健康数据

**流程**：
```
语音闲聊：
1. 老人对 Hub 说："小银小银，陪我聊聊天"
   ↓
2. Hub 麦克风采集语音，ASR 识别
   ↓
3. 云端 LLM 生成回复
   ↓
4. Hub 扬声器播报回复
   ↓
5. 对话记录保存，家属可查看

健康数据语音记录：
1. 老人说："我今天血压130/80"
   ↓
2. ASR 识别 + LLM 结构化提取
   ↓
3. 数据存入健康档案
   ↓
4. Hub 语音确认："已记录，血压130/80，属于正常范围"
   ↓
5. 异常数据自动告警家属
```

**技术要点**：
- Hub端：远场麦克风阵列，降噪处理
- 云端：ASR/TTS 引擎，LLM 对话模型
- 数据结构化：自然语言 → JSON 格式

---

### 5. 异常告警推送家属 📱

**场景**：检测到异常情况，需要通知家属

**告警类型**：
- SOS 紧急呼救（最高优先级）
- 跌倒检测
- 心率异常（过快/过慢）
- 长时间静止（可能晕倒）
- 用药遗漏
- 环境异常（温度、湿度）

**推送通道**：
- APP 推送（即时）
- 短信通知（重要告警）
- 电话呼叫（SOS）

**流程**：
```
1. 手环/Hub 检测到异常
   ↓
2. AI Agent 判定告警等级
   - 紧急：SOS、跌倒 → 电话+短信+APP
   - 重要：心率异常、长时间静止 → 短信+APP
   - 一般：久坐提醒、用药提醒 → APP
   ↓
3. Hub 通过 WiFi 上报云端
   ↓
4. 云端调用 MCP 工具推送
   ↓
5. 家属收到告警通知
   ↓
6. 家属可远程查看老人状态
```

**技术要点**：
- AI Agent：事件分级，避免误报打扰
- MCP 工具：多通道消息推送
- 云端：告警去重，升级机制

## 💻 技术方案

### 手环端技术栈

```
操作系统：openvela（基于 NuttX）
UI 框架：LVGL
传感器驱动：六轴 IMU（I2C/SPI）
无线协议：BLE 5.0 GATT
开发语言：C
构建系统：CMake + Make
```

**关键实现**：
- LVGL 界面：大字体、高对比度、老人友好
- IMU 算法：端侧运动识别，低功耗运行
- BLE 服务：GATT Server，自定义 Service/Characteristic
- 电源管理：动态调频，休眠唤醒

---

### Hub端技术栈

```
操作系统：openvela（基于 NuttX）
AI 框架：AI Agent 框架
音频处理：ASR/TTS 库
网络：WiFi + HTTP/MQTT
UI：LCD 驱动 + 自定义 UI
开发语言：C/C++ + Python（AI）
```

**关键实现**：
- AI Agent：事件驱动，状态机管理
- 语音交互：远场拾音，回声消除
- 云端通信：MQTT 长连接，HTTP REST API
- UI 设计：大字体，高对比度，语音提示

---

### 云端技术栈

```
AI 模型：LLM（对话、ASR、TTS）
后端：Python + FastAPI
数据库：PostgreSQL + Redis
消息队列：RabbitMQ
推送服务：极光推送 / 个推
```

**关键实现**：
- LLM 集成：对话生成，数据结构化
- MCP 工具：消息推送接口
- 数据分析：健康趋势，异常识别
- 安全合规：数据加密，隐私保护
