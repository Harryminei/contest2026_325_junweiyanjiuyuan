## ⚠️ 功能 1：SOS 一键呼救

### 功能定义

**目标**：老人遇到紧急情况时，能够快速、可靠地通知家属或急救中心

**核心价值**：
- 秒级响应，缩短救援时间
- 操作简单，一键触发
- 多通道通知，确保送达
- 位置信息，辅助救援

### 用户场景

**场景1：突发疾病**
```
时间：晚上 9点
地点：家中客厅
情况：老人突感胸闷、呼吸困难
操作：长按手环 SOS 按键 3 秒
结果：
  - 手环震动，屏幕显示"SOS已发送"
  - Hub 语音播报："已收到求助，正在通知家属"
  - 家属手机收到推送："父亲触发SOS紧急呼救"
  - 家属拨打电话，Hub 自动接听
  - 老人通过 Hub 扬声器与家属通话
```

**场景2：跌倒受伤**
```
时间：下午 3点
地点：家中厨房
情况：老人不慎滑倒，无法起身
操作：按下手环 SOS 按键
结果：
  - 系统自动检测跌倒（如已启用）
  - 自动触发 SOS 流程
  - 家属收到告警，立即赶往或呼叫急救
```

**场景3：误触发**
```
时间：上午 10点
地点：家中
情况：老人不小心碰到 SOS 按键
操作：手环提示"是否取消SOS？"
结果：
  - 老人 10 秒内按任意键取消
  - 系统记录误触发日志
  - 不通知家属，避免打扰
```

### 交互流程

```
用户操作：
  长按 SOS 按键 3 秒
      ↓
手环响应：
  - 震动反馈（持续震动）
  - 屏幕显示倒计时（3, 2, 1）
  - 屏幕显示"SOS已发送"
      ↓
BLE 通知 Hub：
  - 发送 SOS 告警数据包
  - 包含：告警类型、时间戳、电量
      ↓
Hub 响应：
  - 扬声器播报："已收到求助，正在通知家属"
  - LCD 显示 SOS 动画
  - 连接 WiFi，上报云端
      ↓
云端处理：
  - 验证告警有效性
  - 查询家属联系方式
  - 调用 MCP 工具推送
      ↓
家属通知：
  - APP 推送（即时）
  - 短信通知（10秒后）
  - 电话呼叫（30秒后，如未确认）
      ↓
后续处理：
  - 家属确认收到
  - Hub 语音提示："家属已收到通知"
  - 记录事件日志
```

### 技术实现

**手环端实现**：
```c
/* SOS 按键处理 */
#define SOS_PRESS_DURATION  3000  /* 3秒 */
#define SOS_CANCEL_TIMEOUT  10000 /* 10秒取消窗口 */

void sos_button_handler(void) {
    static uint32_t press_start = 0;

    if (is_button_pressed()) {
        if (press_start == 0) {
            press_start = get_tick();
        } else if (get_tick() - press_start >= SOS_PRESS_DURATION) {
            /* 触发 SOS */
            trigger_sos();
        }
    } else {
        if (press_start > 0 &&
            get_tick() - press_start < SOS_PRESS_DURATION) {
            /* 按键时间不足，取消 */
            press_start = 0;
        }
    }
}

void trigger_sos(void) {
    /* 1. 震动反馈 */
    motor_vibrate(VIBRATE_PATTERN_SOS);

    /* 2. 屏幕显示 */
    ui_show_sos_screen();

    /* 3. BLE 通知 Hub */
    ble_send_sos_alert();

    /* 4. 启动取消定时器 */
    start_timer(SOS_CANCEL_TIMEOUT, sos_cancel_callback);
}
```

**Hub端实现**：
```c
/* SOS 事件处理 */
void handle_sos_event(sos_event_t *event) {
    /* 1. 语音播报 */
    audio_play("已收到求助，正在通知家属");

    /* 2. LCD 显示 */
    ui_show_sos_alert(event);

    /* 3. 上报云端 */
    cloud_report_sos(event);

    /* 4. 启动通知流程 */
    start_notification_flow(event);
}

/* 通知流程 */
void start_notification_flow(sos_event_t *event) {
    /* 立即：APP 推送 */
    push_notification(event->user_id, "SOS 紧急呼救");

    /* 10秒后：短信 */
    schedule_task(10000, send_sms, event);

    /* 30秒后：电话（如未确认）*/
    schedule_task(30000, make_call, event);
}
```

### 防误触设计

**物理防误触**：
- 按键需要长按 3 秒
- 按键位置隐蔽，不易误碰
- 按键力度适中，避免轻触触发

**软件防误触**：
- 触发后 10 秒内可取消
- 取消操作简单（按任意键）
- 记录误触发日志，优化阈值

**智能防误触**：
- 结合 IMU 数据判断是否真的跌倒
- 分析按键模式，识别误操作
- 机器学习模型，提升准确率

## 🪑 功能 2：久坐/长时间静止检测

### 功能定义

**目标**：检测老人长时间不活动状态，及时提醒活动，预防健康风险

**核心价值**：
- 预防久坐引发的健康问题
- 及时发现异常静止（可能晕倒）
- 养成健康生活习惯
- 家属远程了解活动情况

### 用户场景

**场景1：久坐提醒**
```
时间：下午 2点
地点：家中沙发
情况：老人看电视超过 1 小时未活动
触发：手环检测到久坐
响应：
  - 手环轻微震动
  - 屏幕显示："您已坐了60分钟，起来活动一下吧"
  - Hub 语音播报同样内容
  - 老人起身活动后，提醒重置
```

**场景2：异常静止告警**
```
时间：凌晨 3点
地点：家中卧室
情况：老人可能晕倒，2小时未活动
触发：手环检测到长时间静止
响应：
  - 手环持续震动
  - 屏幕显示："检测到异常，是否需要帮助？"
  - Hub 语音播报并显示告警
  - 如无回应，自动触发 SOS 流程
  - 通知家属关注
```

**场景3：正常睡眠**
```
时间：晚上 11点 - 早上 7点
地点：家中卧室
情况：老人正常睡觉
触发：检测到静止，但时间在睡眠时段
响应：
  - 不触发久坐提醒
  - 不触发异常告警
  - 记录睡眠数据
```

### 交互流程

```
传感器采集：
  六轴 IMU 持续采集（100Hz）
      ↓
端侧算法：
  低通滤波 → 特征提取 → 运动分类
      ↓
状态判定：
  ┌─────────────────────────────────────┐
  │ 状态        条件              响应  │
  │ ─────────────────────────────────── │
  │ 活动        持续运动           无    │
  │ 久坐        静止≥60分钟       提醒  │
  │ 异常静止    静止≥2小时        告警  │
  │ 睡眠        夜间+静止         记录  │
  └─────────────────────────────────────┘
      ↓
手环响应：
  - 久坐：轻微震动 + 屏幕提示
  - 异常：持续震动 + 屏幕告警 + 确认询问
      ↓
BLE 通知 Hub：
  - 上报活动状态变化
  - 包含：状态类型、持续时间、时间戳
      ↓
Hub 响应：
  - 久坐：语音提醒
  - 异常：语音告警 + LCD 显示 + 云端上报
      ↓
云端处理：
  - 记录活动数据
  - 生成活动报告
  - 异常时通知家属
```

### 检测算法

**运动状态分类**：
```c
typedef enum {
    MOTION_STATIC,    /* 静止 */
    MOTION_WALKING,   /* 步行 */
    MOTION_RUNNING,   /* 跑步 */
    MOTION_OTHER      /* 其他运动 */
} motion_state_t;

/* 特征提取 */
typedef struct {
    float acc_mean;      /* 加速度均值 */
    float acc_variance;  /* 加速度方差 */
    float gyro_mean;     /* 陀螺仪均值 */
    float gyro_variance; /* 陀螺仪方差 */
    uint16_t step_count; /* 步数 */
} imu_features_t;

/* 运动状态分类 */
motion_state_t classify_motion(imu_features_t *features) {
    if (features->acc_variance < STATIC_THRESHOLD &&
        features->gyro_variance < STATIC_THRESHOLD) {
        return MOTION_STATIC;
    } else if (features->step_count > 0) {
        if (features->acc_mean > WALKING_THRESHOLD) {
            return MOTION_RUNNING;
        } else {
            return MOTION_WALKING;
        }
    } else {
        return MOTION_OTHER;
    }
}
```

**久坐检测状态机**：
```c
typedef enum {
    STATE_ACTIVE,
    STATE_SITTING,
    STATE_STILL_LONG,
    STATE_SLEEPING
} activity_state_t;

/* 久坐检测阈值 */
#define SITTING_THRESHOLD    (60 * 60)   /* 60分钟 */
#define STILL_THRESHOLD      (2 * 60 * 60) /* 2小时 */
#define SLEEP_START_HOUR     22  /* 晚上10点 */
#define SLEEP_END_HOUR       7   /* 早上7点 */

activity_state_t update_activity_state(motion_state_t motion,
                                        uint32_t duration) {
    static activity_state_t state = STATE_ACTIVE;
    uint8_t current_hour = get_current_hour();

    /* 判断是否在睡眠时段 */
    bool is_sleep_time = (current_hour >= SLEEP_START_HOUR ||
                          current_hour < SLEEP_END_HOUR);

    if (motion == MOTION_STATIC) {
        if (is_sleep_time) {
            state = STATE_SLEEPING;
        } else if (duration >= STILL_THRESHOLD) {
            state = STATE_STILL_LONG;
            trigger_alert();  /* 触发异常告警 */
        } else if (duration >= SITTING_THRESHOLD) {
            state = STATE_SITTING;
            trigger_reminder();  /* 触发久坐提醒 */
        }
    } else {
        state = STATE_ACTIVE;
    }

    return state;
}
```

### 技术实现

**IMU 数据采集**：
```c
/* IMU 采集任务 */
void imu采集_task(void *arg) {
    imu_data_t data;

    while (1) {
        /* 采集 IMU 数据 */
        imu_read(&data);

        /* 低通滤波 */
        imu_filter(&data);

        /* 提取特征 */
        imu_features_t features;
        extract_features(&data, &features);

        /* 运动状态分类 */
        motion_state_t motion = classify_motion(&features);

        /* 更新久坐状态 */
        update_activity_state(motion, get_still_duration());

        /* 休眠 10ms（100Hz 采样率）*/
        usleep(10000);
    }
}
```

**BLE 上报**：
```c
/* 活动状态变化时上报 */
void on_activity_state_change(activity_state_t new_state) {
    activity_report_t report = {
        .state = new_state,
        .duration = get_still_duration(),
        .timestamp = get_timestamp(),
        .battery = get_battery_level()
    };

    ble_notify_activity_status(&report);
}
```

## 💊 功能 3：用药提醒

### 功能定义

**目标**：帮助老人按时服药，避免遗忘，提高用药依从性

**核心价值**：
- 准时提醒，避免漏服
- 大字显示，信息清晰
- 语音播报，双重提醒
- 记录服药，家属可查

### 用户场景

**场景1：日常用药提醒**
```
时间：早上 8点（设定的服药时间）
地点：家中
情况：老人该吃降压药了
流程：
  1. Hub 定时任务触发
  2. LCD 大字显示用药信息
  3. 扬声器语音播报
  4. 手环屏幕同步显示，震动提醒
  5. 老人点击"确认服药"
  6. 记录服药时间
  7. 推送给家属："老人已服药"
```

**场景2：多次提醒**
```
时间：早上 8点
情况：老人可能没听到第一次提醒
流程：
  1. 第一次提醒（8:00）
  2. 5分钟后未确认，第二次提醒（8:05）
  3. 再过5分钟未确认，第三次提醒（8:10）
  4. 三次后仍未确认，通知家属关注
```

**场景3：多种药物**
```
时间：晚上 8点
情况：老人需要服用多种药物
显示：
  该吃药了！
  1. 降压药 - 1片
  2. 降糖药 - 2片
  3. 钙片 - 1片

  请逐一确认服用
```

```
  - 服药时间
  - 剂量

      ↓
定时触发：
  Hub 定时任务检测到提醒时间
      ↓
Hub 响应：
  - LCD 显示用药信息（大字体）
  - 扬声器语音播报
  - BLE 通知手环
      ↓
手环响应：
  - 屏幕同步显示
  - 震动提醒
      ↓
用户确认：
  - Hub 触摸屏点击"确认"
  - 或手环按键确认
      ↓
记录保存：
  - 记录服药时间
  - 推送给家属
      ↓
未确认处理：
  - 5分钟后重复提醒
  - 最多3次
  - 3次后通知家属
```

```c
typedef struct {
    char drug_name[32];
    uint8_t hour;
    uint8_t minute;
    uint8_t dosage;
    char notes[64];
    uint8_t repeat_count;  /* 已重复提醒次数 */

/* 定时任务检查 */
void check_medication_reminders(void) {
    uint8_t hour = get_current_hour();
    uint8_t minute = get_current_minute();

    for (int i = 0; i < plan_count; i++) {
        medication_plan_t *plan = &plans[i];

        if (plan->hour == hour && plan->minute == minute &&
            !plan->confirmed) {
            /* 触发提醒 */
            trigger_medication_reminder(plan);
        }
    }
}

/* 触发提醒 */
void trigger_medication_reminder(medication_plan_t *plan) {
    /* LCD 显示 */
    ui_show_medication_reminder(plan);

    /* 语音播报 */
    char text[128];
    snprintf(text, sizeof(text),
             "该吃药了！%s，剂量%d%s",
             plan->drug_name, plan->dosage, "片");
    audio_play(text);

    /* BLE 通知手环 */
    ble_notify_medication(plan);

    /* 启动未确认定时器 */
    start_timer(5 * 60 * 1000, medication_timeout_callback, plan);
}
```

```c
        if (response->health_data.type != NULL) {

            if (response->health_data.alert_level != ALERT_NONE) {
                trigger_health_alert(&response->health_data);
            }

        save_conversation(text, response->text);
    }
```

## 📱 功能 5：异常告警推送家属

### 功能定义

**目标**：检测到异常情况时，及时、准确地通知家属，确保老人安全

**核心价值**：
- 多级告警，避免打扰
- 多通道推送，确保送达
- 智能去重，减少冗余
- 升级机制，紧急响应

### 告警等级

| 等级 | 名称 | 触发条件 | 推送通道 | 响应时间 |
|------|------|---------|----------|---------|
| 紧急 | CRITICAL | SOS、跌倒、心率异常 | APP+短信+电话 | <10秒 |
| 重要 | HIGH | 长时间静止、血压异常 | APP+短信 | <1分钟 |
| 一般 | MEDIUM | 久坐提醒、用药提醒 | APP | <5分钟 |
| 低 | LOW | 健康数据正常记录 | APP | <30分钟 |

### 告警流程

```
事件检测：
  手环/Hub 检测到异常事件
      ↓
本地处理：
  - 验证事件有效性
  - 去除误报
  - 判定告警等级
      ↓
上报云端：
  通过 WiFi/MQTT 上报
      ↓
云端处理：
  - 告警去重（5分钟内相同事件合并）
  - 升级判断（10分钟未响应则升级）
  - 查询家属配置
      ↓
消息推送：
  - APP 推送：即时送达
  - 短信：10秒延迟
  - 电话：30秒延迟（仅紧急）
      ↓
家属响应：
  - APP 确认收到
  - 电话接听
  - 标记已处理
      ↓
记录归档：
  - 保存告警记录
  - 更新统计报表
```

### 技术实现

**告警上报**：
```c
/* 告警数据结构 */
typedef struct {
    char alert_id[32];
    char user_id[32];
    alert_level_t level;
    alert_type_t type;
    char message[256];
    uint32_t timestamp;
    char source[16];  /* "band" or "hub" */
    json_object *extra_data;
} alert_t;

/* 上报告警 */
void report_alert(alert_t *alert) {
    /* 本地日志 */
    log_alert(alert);

    /* 上报云端 */
    json_object *json = alert_to_json(alert);
    mqtt_publish("alerts", json);

    /* Hub 端显示 */
    if (alert->level >= ALERT_HIGH) {
        ui_show_alert(alert);
    }
}
```
