#### 3. 云端服务层
**职责**：
- LLM 对话和推理

#### 1.3 IMU 运动检测

**算法流程**：
```
原始数据采集 (100Hz)
      ↓
低通滤波（去除噪声）
      ↓
特征提取（加速度均值、方差、峰值）
      ↓
运动状态分类（静止、步行、跑步、跌倒）
      ↓
状态机判定（久坐、长时间静止）
      ↓
触发提醒/告警
```

**关键代码**：
```c
/* 久坐检测状态机 */
typedef enum {
    STATE_ACTIVE,      /* 活动状态 */
    STATE_SITTING,     /* 久坐状态 */
    STATE_STILL,       /* 静止状态 */
    STATE_ALERT        /* 告警状态 */
} activity_state_t;

/* 状态转换逻辑 */
activity_state_t update_activity_state(imu_data_t *data) {
    static uint32_t still_start_time = 0;
    static activity_state_t current_state = STATE_ACTIVE;

    if (is_still(data)) {
        if (current_state == STATE_ACTIVE) {
            still_start_time = get_tick();
            current_state = STATE_SITTING;
        } else if (current_state == STATE_SITTING) {
            if (get_tick() - still_start_time > SITTING_THRESHOLD) {
                current_state = STATE_STILL;
                trigger_reminder();  /* 触发久坐提醒 */
            }
        } else if (current_state == STATE_STILL) {
            if (get_tick() - still_start_time > STILL_THRESHOLD) {
                current_state = STATE_ALERT;
                trigger_alert();  /* 触发静止告警 */
            }
        }
    } else {
        current_state = STATE_ACTIVE;
    }

    return current_state;
}
```

#### 1.4 BLE 通信协议

**GATT 服务设计**：
```
Service: Silver Guardian Service (UUID: 0x1820)
  ├── Characteristic: SOS Alert (UUID: 0x2A01)
  │     Properties: Read, Notify
  │     Value: uint8 (0: normal, 1: SOS triggered)
  │
  ├── Characteristic: Activity Status (UUID: 0x2A02)
  │     Properties: Read, Notify
  │     Value: uint8 (0: active, 1: sitting, 2: still)
  │
  ├── Characteristic: Health Data (UUID: 0x2A03)
  │     Properties: Read, Notify
  │     Value: struct { heart_rate, spo2, steps }
  │
  └── Characteristic: Sync Command (UUID: 0x2A04)
        Properties: Write
        Value: uint8 (command code)
```

**数据上报策略**：
- SOS：立即上报
- 久坐/静止：检测到后上报
- 健康数据：每 5 分钟上报一次
- 心率异常：立即上报

```
│  └─────────┘ └─────────┘ └─────────┘│
└─────────────────────────────────────┘
```

**事件分级**：
```c
typedef enum {
    EVENT_LEVEL_LOW,      /* 低优先级：久坐提醒 */
    EVENT_LEVEL_MEDIUM,   /* 中优先级：用药提醒 */
    EVENT_LEVEL_HIGH,     /* 高优先级：心率异常 */
    EVENT_LEVEL_CRITICAL  /* 紧急：SOS、跌倒 */
} event_level_t;

/* 事件处理优先级 */
void process_event(event_t *event) {
    switch (event->level) {
        case EVENT_LEVEL_CRITICAL:
            /* 立即处理，中断其他任务 */
            handle_critical_event(event);
            break;
        case EVENT_LEVEL_HIGH:
            /* 尽快处理，暂停低优先级任务 */
            handle_high_priority_event(event);
            break;
        case EVENT_LEVEL_MEDIUM:
            /* 正常处理 */
            handle_medium_priority_event(event);
            break;
        case EVENT_LEVEL_LOW:
            /* 空闲时处理 */
            handle_low_priority_event(event);
            break;
    }
}
```

#### 2.2 音频处理

**ASR 流程**：
```
麦克风采集 → 降噪 → VAD检测 → 语音分帧 → 云端ASR → 文本
```

**TTS 流程**：
```
文本 → 云端TTS → 音频流 → 解码 → 扬声器播放
```

**关键技术**：
- 远场拾音：双麦克风阵列，波束成形
- 回声消除：AEC 算法，避免自干扰
- 噪声抑制：NS 算法，提升识别率
- VAD 检测：语音活动检测，节省带宽

## 🎯 技术难点与解决方案

### 1. 低功耗设计
**难点**：手环需要 7 天以上续航
**方案**：
- 动态调频调压
- 传感器按需采集
- BLE 连接参数优化
- 深度休眠策略

### 2. 端侧智能
**难点**：资源受限设备上的 AI 推理
**方案**：
- 轻量级模型（TinyML）
- 特征工程优化
- 模型量化压缩
- 硬件加速（如有）

### 3. 实时性保障
**难点**：SOS 等紧急场景的响应时间
**方案**：
- 中断驱动
- 优先级调度
- 本地决策优先
- 网络异步处理

### 4. 多模态交互
**难点**：语音、视觉、触觉的协同
**方案**：
- 事件驱动架构
- 状态机管理
- 异步处理
- 优先级队列

### 5. 数据一致性
**难点**：手环、Hub、云端的数据同步
**方案**：
- 时间戳同步
- 冲突检测
- 最终一致性
- 补偿机制
