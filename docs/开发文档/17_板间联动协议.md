# 17 板间联动协议（Hub ↔ 手环）

> 2026-09-13 制定。Hub 侧接收端已实现并编入固件（构建标记 `SGHUB-BUILD-20260913-LINK`，版本 1.9.0）。
> 手环端按本文实现发送端即可联通。

---

## 1. 总体方式

两块板子**接同一个 WiFi**，手环主动往 Hub 发 **UDP 报文**，Hub 常驻监听。

```
   ┌──────────────┐        WiFi (同一网段)        ┌──────────────┐
   │  手环端       │  ──── UDP → 5555 ──────────▶ │  Hub 端       │
   │  (发送方)     │                               │  (监听方)     │
   └──────────────┘                               └──────────────┘
                                                        │
                                          翻译成事件 → 提示音 + 屏幕警示层
                                                      + 指示灯 + 事件记录
```

**为什么是 UDP 而不是 TCP**：告警是"一次性、要快、丢了也得能重发"的场景。
UDP 无需握手重连，Hub 掉线重启后手环不用做任何恢复动作，继续发就行。
可靠性靠**手环侧重发**（见 §5）而不是靠 TCP。

**为什么手环主动发**：Hub 是常驻设备、IP 由 DHCP 分配可能变化；
手环只要知道 Hub 的 IP 即可。Hub 侧不需要知道手环的 IP —— 靠心跳超时
判断在线即可。

---

## 2. 报文格式

一行一条，ASCII 文本，`\n` 结尾（`\r\n` 也接受，接收端会去掉行尾空白）。

```
SG1 <类型> [参数...]\n
```

- `SG1 ` 是**定长 4 字节前缀**（大写 S、G、数字 1、一个空格）
- 前缀里带版本号，将来加字段或改协议时，Hub 能据此识别并区分处理
- Hub 收到不以 `SG1 ` 开头的报文会**丢弃并记日志**，不影响运行
- 单条报文最长 **128 字节**，超长会被截断

---

## 3. 报文类型（当前已实现）

| 报文 | 含义 | Hub 侧行为 |
|---|---|---|
| `SG1 SOS` | 老人按下呼救键 | **紧急求助**：红色指示灯快闪 4Hz（保持 5 分钟）+ 屏幕弹出"紧急求助"警示层 + 提示音 + 云端告警桩 |
| `SG1 SOS_CANCEL` | 取消呼救 | 收起警示层 + 熄灭指示灯 |
| `SG1 FALL` | 跌倒检测触发 | **按 SOS 处理**。理由：老人可能已无法自己按键，少一级确认比多一级安全 |
| `SG1 SITTING <秒>` | 久坐判定 | **久坐提醒**：黄色指示灯慢闪 1Hz（30 秒）+ 屏幕"久坐提醒"警示层，正文显示分钟数 |
| `SG1 RESUMED` | 恢复活动 | 收起警示层 + 熄灭指示灯 |
| `SG1 HB` | 心跳 | 只更新"手环在线"状态，**不产生事件**（每 10 秒塞一条会把事件记录页刷爆） |
| `SG1 IMU <x> <y> <z>` | 原始加速度 | 预留。当前只落日志，将来要在 Hub 侧复算姿态时再解析 |

### 示例

```
SG1 HB
SG1 SITTING 1800
SG1 SOS
SG1 SOS_CANCEL
```

## 4. 手环端实现要点

1. **目标**：Hub 的 IP + UDP 端口 **5555**
2. **心跳**：每 **10 秒**发一条 `SG1 HB`。Hub 侧超过 **30 秒**没收到任何报文
   就判定手环离线（`diag.txt` 里 `[联动] 手环在线` 会变"否"）
3. **告警重发**：SOS / FALL 这类关键报文，建议**连发 3 次、间隔 200ms**，
   之后每 2 秒重发一次直到收到用户取消。UDP 会丢包，告警不能只发一次
4. **上电行为**：手环连上 WiFi 后先发一条 `SG1 HB`，让 Hub 立刻知道它来了
5. **不需要等 Hub 回应** —— 协议是单向的，Hub 不回包

### 最小发送示例（伪代码）

```c
int fd = socket(AF_INET, SOCK_DGRAM, 0);
struct sockaddr_in hub = {0};
hub.sin_family = AF_INET;
hub.sin_port   = htons(5555);
hub.sin_addr.s_addr = inet_addr("192.168.1.9");   /* Hub 的实际 IP */

const char *msg = "SG1 SOS\n";
sendto(fd, msg, strlen(msg), 0, (struct sockaddr *)&hub, sizeof(hub));
```

## 5. Hub 侧怎么查联动状态

Hub 每 30 秒把自检报告写到 `/data/silver_guardian/diag.txt`，里面有 `[联动]` 段：

```
[联动] 监听: 就绪 (UDP 5555)
  手环在线    : 是
  累计收报文  : 42 条, 丢弃 0 条
  最近收到    : 有
```

排查时：

```bash
adb shell "cat /data/silver_guardian/diag.txt"      # 看联动段
adb shell "dmesg" | grep -i link                    # 看收包/丢弃日志
```

`丢弃 N 条` 不为 0 说明：要么报文格式不对（日志里会打出原文），
要么一瞬间来太多把 8 条深度的队列挤满了。

## 6. 不用手环也能自测（重要）

Hub 起来后，用电脑直接冒充手环发一条报文就能验证整条链路：

```bash
# Windows PowerShell（把 192.168.1.9 换成 Hub 的实际 IP）
$udp = New-Object System.Net.Sockets.UdpClient
$b = [Text.Encoding]::ASCII.GetBytes("SG1 SOS`n")
$udp.Send($b, $b.Length, "192.168.1.9", 5555)
$udp.Close()
```

发完 Hub 屏幕应该立刻弹"紧急求助"、指示灯变红快闪。
**这是给同事最快的验证手段 —— 不用等手环端做完就能确认 Hub 侧的接收链路是通的。**

## 7. 设计取舍记录

| 决定 | 理由 |
|---|---|
| 用 UDP 不用 TCP | 告警场景要快，且 Hub 重启后手环无需重连；可靠性交给应用层重发 |
| 文本协议不用二进制 | 现场调试能直接 `echo` 一条报文验证，二进制做不到 |
| 前缀带版本号 `SG1` | 将来加字段不至于把老报文认错 |
| 心跳不产生事件 | 每 10 秒一条会把"事件记录"页刷爆 |
| `FALL` 直接按 SOS 处理 | 老人跌倒后可能无法自己按键，宁可误报也不能漏报 |
| Hub 不回包 | 保持单向，手环端实现最简单；Hub 的在线状态由心跳超时推断 |

## 8. 后续可扩展方向

- `SG1 BAT <百分比>` —— 手环电量，Hub 低电时提醒家属
- `SG1 HR <心率>` —— 接入心率后走健康数据页
- `SG1 ACK <序号>` —— 若将来需要确认送达（当前靠重发，不需要）
- 反向通道：Hub → 手环（例如"该吃药了"推到手表震动），
  目前协议是单向的，要做的话建议另开端口而非复用 5555
